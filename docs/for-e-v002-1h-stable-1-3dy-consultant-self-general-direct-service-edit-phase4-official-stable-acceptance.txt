階段：第四階段補充修正

一、顧問新增一般行程
1. 顧問新增表單的行程類別仍只顯示「一般行程」。
2. 表單不顯示「選擇部門」。
3. 執行人員固定顯示顧問本人，不提供其他人員勾選。
4. 從行程總覽點選越雙語其他人員欄位的空白日期新增時，仍固定指派顧問本人。
5. 儲存後 schedule_assignees 只新增顧問本人，不會新增被點選欄位的人員。
6. 行程資料的部門資料自動沿用顧問本人既有部門，不需要手動選擇。

二、顧問修改別人指派的服務行程
1. 由其他人建立、但 schedule_assignees 直接包含目前顧問的非提醒服務行程，查看明細應顯示「修改行程」。
2. 顧問可以進入修改表單並儲存內容。
3. 原本指定越雙語人員相關服務行程的修改權限維持不變。
4. 未直接指派顧問、且與指定越雙語人員無關的服務行程仍不可修改。

三、服務行程限制維持
1. 顧問對服務行程只能修改內容與執行者。
2. 不顯示、也不能執行「已完成」。
3. 不顯示、也不能執行「取消／刪除」。
4. 提醒事項仍維持唯讀。
5. 外務行程與外務日仍維持唯讀。

四、既有顧問設定維持
1. 左側只顯示個人行程表、行程總覽、行程搜尋、人員帳號。
2. 固定快速群組「越雙語」及顧問本人置頂維持不變。
3. 九位越雙語人員名單與排序不變。
4. 顧問角色 staff_role_check 使用既有 1-3dt SQL，本版沒有新增 SQL。

五、資料安全
1. 不修改 Supabase schema。
2. 不更新或重寫既有正式行程。
3. 不重建 schedules、schedule_id 或 schedule_assignees。
4. 不修改日期、週期、LINE、提醒通知、統計、會議室、外務資料流程或服務紀錄單。
5. 第五階段「統一表單欄位設定」尚未開始。
