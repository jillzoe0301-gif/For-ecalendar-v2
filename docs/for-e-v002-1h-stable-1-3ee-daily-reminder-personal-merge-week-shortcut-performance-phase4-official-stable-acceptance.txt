一、今日提醒一天只跳一次
1. 同一帳號當天第一次登入／首次載入系統：若有今日提醒，會跳「今日提醒」。
2. 關閉後登出再登入：當天不再重複跳。
3. 同一天重新整理頁面：不再重複跳。
4. 同一天開新分頁／重新開瀏覽器：同一帳號不再重複跳。
5. 隔天第一次登入：可再次正常跳當日提醒。
6. 不清除整個 localStorage；只新增目前登入帳號的最後提醒日期紀錄。

二、個人行程表＋個人一般待辦合併
1. 左側／手機底部不再出現獨立「個人一般待辦」。
2. 「個人行程表」內同時顯示：
   - 當日一般行程提醒
   - 當日一般待辦提醒（一般記事／待辦事項／辦件提醒／證件交付）
   - 今日會議
   - 服務紀錄提醒
   - 待確認／待通知提醒
   - 逾期任務
   - 個人全部行程列表
3. 原有新增行程功能保留；各角色原本可建立的類別不因合併而減少。
4. 舊 personalTodo render 邏輯保留為相容後備，但不再作為獨立功能頁。

三、個人當週行程按鈕
1. 行程總覽上方新增「個人當週行程」。
2. 電腦、平板、手機皆可見。
3. 點擊後：
   - 檢視範圍切為「個人當週」
   - 顯示目前登入者
   - 回到本週
   - 清除快速群組選取，activeId 回到 all
4. 已在個人當週時按鈕使用主要按鈕樣式提示目前狀態。

四、登入／切頁效能
根因與修正：
1. 原本登入：auth.getUser → profile RPC → 單筆 staff 查詢 → refreshData 再抓整份 staff，形成串行等待。
   修正：使用 signIn / session 既有 user；profile RPC 與完整 staff 平行讀取；若 staff 已載入，refreshData 不再重抓 staff。
2. 原本 render 前等待「最後登入紀錄」寫入 app_settings / profiles。
   修正：首頁先 render，最後登入紀錄延後背景寫入。
3. 原本登入完成立即同時啟動 profiles、audit_logs、service_records、birthday_wishes 背景讀取，與首頁競爭網路資源。
   修正：首屏後延遲載入；若使用者先點到需要該資料的頁面，仍立即載入。
4. 原本第一次切到個人頁時常要再抓 -31～+120 天行程。
   修正：瀏覽器 idle 時背景預載常用個人日期範圍。
5. 原本切頁需要較大日期範圍時會整頁只顯示 loading。
   修正：已有部分 schedule 資料時先立即切頁並顯示現有內容＋讀取提示，再背景補齊日期範圍。
