一、統計報表排除的行程類型
下列 5 種行程不得出現在統計報表，也不得列入行程總數、未完成、已完成、逾期、一部/二部或人員統計：
1. 電表提醒
2. 辦件提醒
3. 驗證提醒
4. 轉出到期最後一天（含既有「轉出追蹤／轉出提醒／轉出最後一天」正規化後的同類型）
5. 加班單繳交

驗收方式：
- 在同一期間內建立或找到上述類型行程，進入統計報表。
- 行程類型下拉選單不應出現上述類型。
- 行程類型統計、一部/二部統計、人員統計、上方總數都不應計入上述資料。
- 原正式行程仍應存在於行程總覽/個人行程等正常頁面，本版只是不列入統計。

二、人員統計只列翻譯角色
1. 人員統計只顯示 role = 翻譯 的啟用人員。
2. 管理員、主管、行政 / 海外、一般職員、顧問、外務 / 宿管人員 / 會計等角色不得出現在人員統計。
3. 所有啟用翻譯都要列出；期間內 0 筆行程的翻譯也要顯示，數字為 0。
4. 同一案件同一翻譯仍只計一次，保留原本一案一算規則。
5. 同一行程同時指派翻譯與行政時，人員統計只計翻譯，不列行政。
6. 舊行程若沒有 schedule_assignees，但建立者本身是翻譯，仍可歸到該翻譯，避免舊資料消失。

三、統計篩選
1. 統計報表「人員」欄改為「翻譯人員」。
2. 下拉選單第一項顯示「全部翻譯」。
3. 下拉選單只顯示啟用的翻譯角色。
4. 若瀏覽器保留了舊版非翻譯人員篩選值，更新後應自動視為「全部翻譯」，不可造成統計整頁空白。

四、不變更項目
- 不修改 Supabase schema。
- 不新增 SQL。
- 不刪除或改寫任何既有行程。
- 不修改 schedule_id / schedule_assignees。
- 不修改角色權限。
- 不修改顧問既有規則。
- 不修改 LINE、外務、會議室、服務紀錄單流程。
- 不進入第五階段「統一表單欄位設定」。

五、程式檢查
- node --check src/main.js 必須通過。
- npm run build 必須在 Codespaces 通過後才可 push main。
